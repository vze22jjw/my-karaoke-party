# Playwright E2E Testing & Visual Reports Dashboard 🧪

This project includes a comprehensive Playwright E2E test suite that simulates real host and guest interactions (such as creating parties, joining as guests, adding songs to the queue, switching languages, and verifying Spotify carousel recommendations).

---

## 🏃‍♂️ Running the Tests

Tests can be run either natively or within a container environment.

### Option 1: Native Test Execution
To run tests natively on your host machine:
```bash
# Install Playwright browser engines
npx playwright install

# Execute tests
npx playwright test tests/core-flow.spec.ts
```

### Option 2: Containerized Test Execution (Recommended)
If your application is running inside a Docker or Podman network (e.g., `mykaraokenetwork`), execute the tests inside the official Playwright container to avoid local system dependency issues:
```powershell
podman run --rm -i \
  --name mykaraoke-e2e \
  --network mykaraokenetwork \
  -w /app \
  -e BASE_URL=http://mykaraoke-app:3000 \
  -e ADMIN_TOKEN=change_this_value_here \
  -e SPOTIFY_CLIENT_ID=your_spotify_client_id_here \
  -e SPOTIFY_CLIENT_SECRET=your_spotify_client_secret_here \
  -e PLAYWRIGHT_REPORTS_MAX_AGE_DAYS=7 \
  -e CI=true \
  -v "${PWD}:/app" \
  mcr.microsoft.com/playwright:v1.57.0-jammy \
  /bin/sh -c "npx playwright test tests/core-flow.spec.ts"
```

## 📊 Live Reports Dashboard

Every time the test suite is run, a new report folder containing screenshots, videos (on failure), and execution traces is created under `public/reports/run-YYYY-MM-DD-HH-mm`.

Additionally, the suite automatically regenerates a clean, central dashboard at `public/reports/index.html` listing all available runs.

### 🌐 Serving the Dashboard via Next.js
The Next.js application is configured to serve these HTML reports securely.

#### 1. Environment Configuration (`.env`)
Make sure the following variables are defined in your `.env` file:
```env
# Allow Next.js middleware to permit/serve playwright reports
SERVE_PLAYWRIGHT_REPORTS=true

# Keep reports disk usage in check (automatically prunes runs older than 7 days)
PLAYWRIGHT_REPORTS_MAX_AGE_DAYS=7
```

#### 2. Crucial Volume Mount for Containerized Hosting ⚠️
Because the Next.js app container runs in an isolated filesystem, **you must mount the host's reports folder** into the container so Next.js can read and serve the reports generated by the host/test runner:
```bash
-v "${PWD}/public/reports:/app/public/reports"
```
For example, when running with `podman run`:
```bash
podman run -d --name mykaraoke-app --network mykaraokenetwork -p 3000:3000 \
  -v "${PWD}/public/reports:/app/public/reports" \
  --env-file .env.resolved my-karaoke-party:app-latest
```

## 🔍 Visual QA & Trace Inspection

Once the app is running and the tests have finished populating reports, navigate to:
👉 **[http://localhost:3000/reports/index.html](http://localhost:3000/reports/index.html)**

### Clickable Screenshots & Emoji Verification
Under any test execution step, click on any thumbnail image to **expand it to full size** for quick visual regression checks. The test suite automatically takes visual confirmation checkpoints:
*   `host-avatar-selected.png`: Verifies the host emoji styling (larger size, ring highlight, shape drop-shadow).
*   `guest-[index]-avatar-selected.png`: Verifies the guest avatar picker form styling.
*   `guest-0-singers-tab-emojis.png`: Confirms custom emojis render properly in the active singer listing and that the active singer's outline glow parses correctly.
*   `guest-0-applause-scene.png`: Verifies the giant clapping emoji layout on the applause screen.

### Interactive Playwright Traces
Because reports are served over `http://` instead of the local browser `file://` protocol, browser security rules allow the Playwright Trace Viewer to load traces seamlessly. Click the **Trace** thumbnail at the bottom of the test results to interactively inspect the DOM, network requests, console logs, and action timings.
